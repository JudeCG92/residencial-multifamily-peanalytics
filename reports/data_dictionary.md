# Data Dictionary — ResidenceAlpha

## Origin of the data

**No real property, resident, or lease appears anywhere in this repository.**

### Synthetic data
Both `data/properties.csv` (40 properties) and `data/leases.csv` (1,249
individual leases) are fabricated, generated by `scripts/generate_residencealpha_data.py`
to match realistic multifamily operating patterns:

- Property-level metrics (occupancy, rent, NOI margin) are calibrated by
  property class (A/B/C) using realistic industry distributions.
- Lease renewal outcomes are drawn from a **logistic model with genuine
  random noise** — depending on rent increase offered, maintenance
  responsiveness, tenure, and property occupancy — so a model trained on
  the data has real signal to find, not a deterministic formula to
  reverse-engineer.
- Resident feedback comments (`feedback_text`) are **template-generated**,
  combining a theme (Maintenance, Noise, Cleanliness, Amenities, Safety,
  Management Responsiveness, Lighting) and a sentiment (positive/negative)
  into short phrasings. **These are not real resident quotes** — they exist
  to give the NLP layer realistic short-text material to classify, and this
  has a real consequence documented in the Model Card: classification
  accuracy on templated text is unrealistically high compared to what a
  model would achieve on genuine free-text resident comments.

### Why simulation was necessary
Real multifamily operating data (rent rolls, lease files, resident
feedback) is proprietary and contains personally identifiable resident
information. Publishing or training on real data of this kind isn't
possible without violating privacy and ownership constraints.

## Field reference

### `data/properties.csv`

| Field | Type | Description |
|---|---|---|
| `property_id` | string | `PR001`–`PR040` |
| `market` | categorical | One of 8 US metros |
| `property_class` | categorical | A / B / C |
| `year_built` | int | 1985–2021 |
| `total_units` | int | Property size |
| `avg_unit_sqft` | float | Average unit size |
| `occupancy_pct` | float | Current physical occupancy |
| `asking_rent_psf` / `effective_rent_psf` | float ($/sqft) | Asking vs. effective (post-concession) rent |
| `loss_to_lease_pct` | float | Gap between asking and effective rent |
| `concession_pct` | float | Average concession as % of rent |
| `annual_revenue` | float ($) | **Calculated** from rent, occupancy, unit count |
| `opex_ratio` | float | Operating expense ratio, by class |
| `noi` / `noi_margin` | float | **Calculated**: revenue × (1 − opex_ratio) |
| `same_property_noi_growth_pct` | float | Trailing NOI growth |
| `maintenance_avg_response_hours` | float | Average maintenance response time |
| `renovation_status` | categorical | None / In Progress / Completed (last 12mo) |
| `capex_per_unit_ytd` | float ($) | Capital spend per unit this year |
| `cap_rate` / `valuation` | float | **Calculated**: NOI / cap_rate, by class |
| `cluster` / `segment` | int / categorical | KMeans cluster + rule-based label (see Model Card) |

### `data/leases.csv`

| Field | Type | Description |
|---|---|---|
| `lease_id` | string | `L00001`–`L01249` |
| `property_id` | string | Links to `properties.csv` |
| `unit_type` | categorical | Studio / 1BR / 2BR / 3BR |
| `tenure_months` | float | Time in current unit |
| `current_rent` / `market_rent` | float | Current vs. market-rate rent |
| `rent_increase_offered_pct` | float | Offered renewal increase |
| `concession_months` | int | Concession months granted |
| `maintenance_requests_count` / `maintenance_avg_response_days` | int / float | Maintenance history |
| `feedback_theme` / `feedback_sentiment` / `feedback_text` | categorical / categorical / string | **Template-generated**, see above |
| `renewed` | binary | **Synthetic target**, drawn from a genuine logistic + noise model |
| `renewal_probability` | float | **Model output** — Random Forest predicted probability |
| `renewal_risk_tier` | categorical | High Renewal Risk (<40%) / Uncertain (40–60%) / Likely to Renew (>60%) |

## What actually drives the renewal target (documented, not hidden)

Renewal probability is generated to depend on: a smaller offered rent
increase (higher renewal), faster maintenance response (higher renewal),
longer tenure (higher renewal), more than 3 maintenance requests (lower
renewal), any concession granted (higher renewal), and property-level
occupancy. Verified empirically in the data: residents who renewed had a
median 3.4% offered increase vs. 5.8% for those who didn't, and 61%
positive feedback sentiment vs. 44% for those who left.
